# Folder inspection and cleanup UX

Updated 14 October 2026. This is a desk review of official documentation, the existing implementation, and the user's reported macOS permission errors. It is not a user study. The goal is to make choosing, inspecting, checking, and confirming cleanup easy to verify.

## Findings and implementation

| Observed issue                                                                       | Decision                                                                                                                                                                                                                                                       | Acceptance check                                                                                                                                                   |
| ------------------------------------------------------------------------------------ | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| Entering absolute paths requires knowing the filesystem layout and invites mistakes. | Make a native folder picker the primary action. Keep validated manual entry available. Allow multiple project roots and one file root. Cancellation changes nothing.                                                                                           | Picker result, cancellation, paths with spaces, and validation are exercised in UI and native tests.                                                               |
| Users cannot inspect what they are about to remove.                                  | Offer Open in Finder on macOS, Open in Explorer on Windows, and Open in file manager on Linux. For files, reveal the item in its containing folder. Offer these actions on scan locations, results, individual artifact folders, and the review.               | Assert the exact opening/reveal command and path; opening never invokes deletion. Show failures inside the current review.                                         |
| A list of 50 protected system paths suggests 50 cleanup failures.                    | Prune macOS system roots, application bundles, and the user's Library when traversing a broad scan. Summarize remaining permission skips with an uncapped count and up to three examples. Keep an unreadable selected root an actionable error.                | Permission fixtures keep readable projects/files visible, count skipped children, and reject an unreadable root. Test macOS path policy separately from traversal. |
| A project name and tags do not show the exact deletion boundary.                     | Show full, wrapping paths and sizes for every artifact folder. Review checkboxes allow correcting a plan; clearing any checkbox resets confirmation. Individual files have their own review checkbox.                                                          | Unchecked targets never reach deletion commands; an empty plan cannot be confirmed; changing the plan clears acknowledgment.                                       |
| Results may belong to a previous folder or scan setting.                             | Record the scanned roots and settings. Display their paths. Block cleanup when roots, recursion, hidden-folder options, or depth change until another scan completes.                                                                                          | Change project roots/depth or the file root after selection and assert Review cleanup is disabled.                                                                 |
| Modal and status changes can interrupt or lose keyboard navigation.                  | Use a native modal dialog, focus its heading initially, contain Tab navigation, close with Escape before deletion, and return focus to the review trigger or results heading. Announce scan coverage and cleanup results as status; identify failures in text. | Exercise initial focus, Tab containment, Escape focus restoration, errors, mixed selection, and narrow viewports.                                                  |

## Sources and why they apply

- [Tauri dialog documentation source](https://github.com/tauri-apps/tauri-docs/blob/main/src/content/docs/plugin/dialog.mdx): native directory selection and Rust `DialogExt`. The app uses narrow custom Rust commands, so it does not need general dialog permissions exposed to JavaScript.
- [Tauri opener documentation source](https://github.com/tauri-apps/tauri-docs/blob/main/src/content/docs/plugin/opener.mdx): opening directories and revealing an item in its file manager. Custom commands validate directories, reject files and application bundles for folder opening, and reveal regular files without launching them.
- [WAI-ARIA modal dialog pattern](https://github.com/w3c/aria-practices/blob/main/content/patterns/dialog-modal/dialog-modal-pattern.html): focus entry, contained keyboard navigation, Escape, and focus restoration. A heading receives initial focus because the review contains several paths and choices.
- [WCAG understanding: status messages](https://github.com/w3c/wcag/blob/main/understanding/21/status-messages.html): announce progress and results without moving focus. Protected-path skips are informational scan coverage, separate from errors requiring correction.
- [WCAG understanding: error identification](https://github.com/w3c/wcag/blob/main/understanding/20/error-identification.html): identify problems in text and tell the user what to correct. A root permission error names the selected folder and suggests an accessible folder or its permissions.
- [WCAG understanding: error prevention for data](https://github.com/w3c/wcag/blob/main/understanding/20/error-prevention-legal-financial-data.html): support review, confirmation, and correction before stored data is removed. Review shows exact paths and allows deselection before permanent deletion.

The published Tauri documentation site, Apple Human Interface Guidelines, and the W3C site were blocked by the cloud environment's network policy during this review. Official GitHub source was used for Tauri and W3C guidance. No claim is made that blocked Apple guidance was read. The official documents describe principles and APIs; plugin versions are pinned to the existing Tauri 2.1.1 toolchain and the actual pinned Rust APIs were inspected and compiled.

## Validation and remaining limits

Automated browser tests use a mocked desktop bridge to verify interaction and command arguments. Rust tests exercise real disposable folders, selection safeguards, symlink handling, permission errors, and navigation validation. The Linux desktop smoke check opened the native folder dialog, selected a disposable project folder, scanned its actual build artifact, and canceled another picker without changing selection. Desktop builds validate native plugin integration; release CI builds macOS universal, Windows, and Linux installers.

This cloud machine cannot inspect the user's Mac. A macOS manual check is still needed for the native picker, Finder opening/reveal behavior, and system permission prompts. Browser tests cannot establish VoiceOver behavior or full accessibility conformance. Disk-space estimates measure file data rather than physical blocks. A successful build does not establish notarization: macOS release signing remains a separate distribution requirement.

For a Mac check: choose Projects using the dialog, open a result in Finder, expand its cleanup folders, inspect one artifact in Finder, select it, open review, uncheck it, verify confirmation resets, then cancel with Escape. Repeat in Downloads using Show in Finder. Use only disposable test targets when checking deletion. Broad scans should report excluded/protected locations as coverage, while choosing an unreadable root should show one actionable error.
